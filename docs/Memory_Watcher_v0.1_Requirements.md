# Memory Watcher v0.1 確定要件

## 1. 文書状態

- 対象リリース: v0.1
- 要件状態: FROZEN（工程11で表示期間と保持期間のみ改訂）
- 対応工程: 工程0「要件固定」、工程11「軽量性・非通信検証」
- 未決定項目: なし

本書はv0.1の対象機能、対象外機能、品質条件、データ境界を固定します。
メモリ値の取得元と導出式は工程3で照合結果とともに版管理しますが、
製品の対象範囲は本書から拡張しません。

2026-08-31のowner指示により、旧表示期間 `24時間・7日・30日` を
`12時間・24時間・3日` へ変更しました。通知、通信、収集項目など、
それ以外の製品境界は変更していません。

## 2. 製品目的

Memory Watcherは、利用者がMac全体のメモリ状態を常時記録し、現在値だけ
では分からない過去の変化、スワップ増加、圧縮増加、スリープ区間を
12時間・24時間・3日の履歴として確認するためのmacOSアプリです。

Activity Monitorの複製ではありません。公開APIで取得可能な情報を用いて
同じ傾向を観察できることを目標とし、完全一致を保証しません。

## 4. 機能要件

### MW-FR-001 測定間隔

アプリ起動中かつ利用者がログイン中のとき、5秒ごとに1回測定します。
測定処理はウインドウの表示状態から独立して動作します。

### MW-FR-002 記録項目

各測定は次を含みます。

- UTC時刻
- システム稼働時間
- 物理メモリ総量
- メモリ使用量
- 有線メモリ
- 圧縮メモリ
- キャッシュ相当量
- スワップ使用量
- メモリプレッシャー状態
- 計算式バージョン

導出値とOSの生カウンターを区別して保存します。負数、総量超過、
単位不整合は保存前検証で拒否または `UNKNOWN` とします。

### MW-FR-003 メモリプレッシャー

状態は `UNKNOWN`、`NORMAL`、`WARNING`、`CRITICAL` の4種類です。
OSから起動直後の状態を確認できない場合は推測せず `UNKNOWN` とします。
独自の連続スコアをActivity Monitorの圧力曲線として表示しません。

### MW-FR-004 ローカル保存

SQLiteデータベースを
`~/Library/Application Support/MemoryWatcher/memory-watcher.sqlite3`
へ保存します。スキーマ移行、トランザクション、整合性検査を備えます。

### MW-FR-005 保存期限と集約

- 5秒の生データ: 24時間
- 1分集約データ: 3日
- 5分集約データ: 3日（既存SQLiteとの互換用）
- 3日超の集約データと低頻度事象: 削除

元データは対応する集約の成功を確認した後にだけ整理します。

### MW-FR-006 履歴表示

12時間・24時間・3日を切り替え、使用量の構成、圧縮、スワップ、
プレッシャー状態を表示します。ポイント選択時には時刻とGB値を表示します。
単位はバイトで保存し、画面ではGBを基本表示とします。

### MW-FR-007 スリープと時刻変更

UTC時刻とシステム稼働時間の差から、スリープ、復帰、時計変更、
再起動を識別します。測定できなかった区間に偽の値を生成せず、
グラフを空白にします。

### MW-FR-008 メニューバー

Dockへ常時表示せず、メニューバーに現在の使用量を簡潔に表示します。
メニューから履歴ウインドウの表示、ログイン時起動の切替、アプリ終了を
操作できます。履歴ウインドウを閉じても測定は継続します。

### MW-FR-009 ログイン時起動

利用者が設定で有効・無効を切り替えられます。初期値は無効です。

## 5. 対象外

v0.1には次を実装しません。

- 通知
- 外向き通信
- 分析送信
- クラウド保存またはクラウド同期
- プロセス別・アプリ別解析
- AIによる診断、要約、推奨
- 自動最適化、プロセス終了、メモリ解放
- Activity Monitorの完全な画面複製
- Activity Monitorとの数値または連続圧力曲線の完全一致保証

## 6. 非機能要件

### MW-NFR-001 軽量性

- アイドル時平均CPU使用率1%未満を目標とする
- 24時間運転でアプリ自身のメモリが単調増加しない
- 3日保持上限のデータベースが実用的な容量に収まる

### MW-NFR-002 表示性能

3日履歴を対象Macで2秒以内に表示します。UI操作中も測定処理を
停止させません。

### MW-NFR-003 信頼性

- 起動中の説明不能な測定欠落を発生させない
- 異常終了後に同じデータベースを再度開ける
- 再起動後も履歴を保持する
- `PRAGMA integrity_check` が `ok` になる

### MW-NFR-004 プライバシー

ランタイムは通知、外向き通信、クラウド保存、分析送信を行いません。
測定データをアプリの保存先以外へ複製しません。

### MW-NFR-005 公開境界

公開リポジトリへ保存できるのは製品ソース、テスト、リソース、
一般向け文書、一般的なビルド補助スクリプトだけです。次は保存しません。

- ローカルの開発調整情報
- 端末固有の絶対パス
- 認可文字列、受領記録、署名材料、資格情報
- 非公開ログ、内部操作の出力
- 製品のビルドまたは実行に不要な開発環境固有ファイル

各コミット、PR、マージ前に公開境界検査を実施します。禁止情報を
マージ前に検出した場合はincidentとして停止します。

## 7. データと通信の境界

| 種類 | 境界 |
|---|---|
| 測定データ | ローカルSQLiteのみ |
| 設定 | ローカルのアプリ設定のみ |
| 外向き通信 | なし |
| 通知 | なし |
| クラウド | なし |
| プロセス情報 | 収集しない |

## 8. Activity Monitorとの差異方針

1. OSの生カウンターと導出値を分離する
2. 各導出式にバージョンを付ける
3. アイドル・通常・高負荷の3条件で照合する
4. 差異を項目単位で説明する
5. 完全一致しない値は誤解のない独自名称または推定表示にする
6. 説明不能な差異が残る場合は工程3をHOLDする
