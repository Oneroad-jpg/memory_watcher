# Memory Watcher v0.2 CPU・統合画面工程表

## 文書状態と対象範囲

- 状態: 工程14完了。工程15は実装・技術検証済みで、PR・merge・remote readback前。
- 着手条件: v0.1の工程12と最終完成ゲートが完了していること。
- 対象: Mac全体のCPU、論理CPU別のCPU、既存のメモリ履歴。
- 表示期間: 12時間・24時間・3日。旧7日・30日表示は追加しない。
- 対象外: GPU、アプリ別・プロセス別解析、AI、通知、外向き通信。

メモリ画面とCPUメーター・CPU履歴を、Memory Watcherの単一ウインドウに
まとめる。Activity Monitorのウインドウを埋め込むのではなく、本アプリが
取得・保存した値を描画する。Activity Monitorの起動や画面取得を、通常利用の
前提にしない。照合時にのみActivity Monitorを参照する。

既存の工程番号13〜17を維持し、工程16と17の間に工程16Aを追加する。
本書の作成は、停止中の工程の再開、実装、監査開始、工程完了を意味しない。

## 工程16Aの画面構成

広いウインドウでは、論理CPU別の小さなグラフを左、メモリと全体CPUの
履歴を右に置く。狭いウインドウでは縦並びへ切り替える。
「1ウインドウ」は、すべてのコアを縮小して1画面に押し込むことではない。
コアが多い場合は同じウインドウ内の縦スクロールで確認できるようにする。

```text
┌ Memory Watcher ───────────────────────────────────┐
│ 現在値: メモリ / CPU全体 / Pressure / 最終測定時刻 │
│ 論理CPU別の現在値メーター                         │
│ 共通表示期間: [12時間] [24時間] [3日]   [更新]     │
├ 論理CPU別の履歴 ───┬ メモリ使用量・構成 ──────────┤
│ CPU 1             │ スワップ                     │
│ CPU 2             │ メモリプレッシャー           │
│ …                 │ CPU全体の履歴                │
├───────────────────┴──────────────────────────────┤
│ 選択時刻: メモリ値 / CPU値 / 実測時刻・集約区間   │
└──────────────────────────────────────────────────┘
```

画面上のCPU番号は保存したCPU indexとの対応を明示する。論理CPUと物理コアを
同一だと断定しない。高性能・高効率の表示は、対応付けを確認できる公開根拠が
ある場合に限る。根拠がない機種では「CPU 1」などの中立な名称を使う。

## 監査・保存・停止の規則

- 工程16Aだけのための独立した24時間監査は増やさない。工程17の24時間監査で、
  メモリ・CPU・統合画面を含む最終構成を検証する。
- 各工程は、新しいphase branch、ちょうど1個の非merge commit、ready PR、
  merge commit、GitHub remote readbackを完了してから次へ進む。
- incident、HOLD、説明不能な差、テスト失敗、公開情報漏洩が出た場合は、その工程で停止する。
- 既存の監査checkpointと観測記録を上書きしない。修正版の再監査は、
  再開が認められた後に別の記録で行う。
- 文書の保存、実装、ビルド、インストール、実運転、マージは別々の状態として報告する。
