# 工程4 メモリプレッシャー取得 検証記録

## 実装範囲

- DispatchのメモリプレッシャーソースでOSの状態変化を監視する
- 状態を `UNKNOWN`・`NORMAL`・`WARNING`・`CRITICAL` の4値で表す
- 各観測にUTC時刻とシステム稼働時間を付ける
- 起動時は現在状態を推測せず、最初の観測を `UNKNOWN` とする
- 同じ状態の反復イベントは新しい状態変化として扱わない
- 複数の状態フラグが同時に届いた場合は優先順位を推測せず
  `UNKNOWN` とする

## 非対象

- 独自の連続的なメモリプレッシャースコア
- Activity Monitorの連続的な圧力曲線の複製
- 状態観測のSQLite保存（工程5）
- メモリプレッシャー通知

## 完了条件と結果

| 完了条件 | 検証結果 |
|---|---|
| `NORMAL`・`WARNING`・`CRITICAL`を識別できる | 単体テストで各OSイベントフラグの対応を確認 |
| 状態変化に時刻を付けられる | UTC時刻と稼働時間を保持する単体テストに合格 |
| 起動直後に状態を推測しない | 実際のDispatch sourceを開始し、初期値が`UNKNOWN`であることを確認 |
| 不明な入力を推測で埋めない | 空および複数フラグを`UNKNOWN`として保持する単体テストに合格 |
| 同じ状態を重複記録しない | 状態機械の重複抑制テストに合格 |
| 独自の連続スコアを作らない | 実装と公開成果物を確認。4値の状態以外を生成しない |
| ビルドと全単体テストが成功する | `swift build`と`swift test`に合格 |

## 判定

工程4は、OSが通知する離散的な状態変化だけを記録可能な形で表現します。
起動時またはイベントが曖昧な場合は `UNKNOWN` を保存対象とし、連続曲線や
現在状態を推測しません。状態観測の永続化は工程5で実装します。
