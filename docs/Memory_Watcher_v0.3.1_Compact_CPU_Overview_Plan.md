# Memory Watcher v0.3.1 上部余白削減・CPU一覧工程表

## 目的と範囲

工程22では、ログイン時起動の行と履歴表示の間にある固定余白を削減し、その高さを
履歴へ渡します。標準幅1,080 points・balanced・8論理CPUでは、論理CPU履歴を
2列4行にしてCPU 1〜8を同一画面内で確認できるようにします。

メモリ・CPUの測定式、5秒間隔、SQLite schema、保持期間、sleep・UNKNOWN・gap、
通信・通知境界は変更しません。16・32論理CPUの値も省略せず、狭いウインドウでは
既存のstacked配置とスクロールへ戻します。

## 工程22

| 実装内容・成果物 | 完了条件 |
|---|---|
| 上部現在値ペインの高さを実内容に近い範囲へ縮める | 利用可能高900 pointsでcompact 126、balanced 144、detailed 162 pointsとなる。標準ウインドウの実コンテンツ高868 pointsでは121.52、138.88、156.24 pointsとなる。ログイン時起動の操作を失わず、履歴領域が各プリセットで従来より広くなる。 |
| 標準幅の論理CPU履歴を2列化する | 1,080 points・balancedで2列分のカード幅とメモリ履歴500 pointsが同時に収まる。8論理CPUが2列4行で表示される。 |
| 狭幅・多CPUのfallbackを維持する | 780 pointsではstacked配置へ戻る。1・8・16・32論理CPUを切り捨てず、画面内に収まらない場合はスクロールで到達できる。 |
| 表示と機能の回帰検証 | 12時間・24時間・3日、メモリ、全体CPU、論理CPU、sleep・UNKNOWN・gap、表示設定、ログイン時起動を退行させない。SQLite schemaと監視エンジンを変更しない。 |
| 公開・導入 | 全テスト、Release build、strict format lint、公開境界scanがPASSする。工程22を1個の非merge commit、ready PR、merge commit、remote readbackで完了し、v0.3.1をインストールして実行バイトと履歴読戻しを確認する。 |

## 停止規則

- 表示欠け、重なり、CPU欠落、履歴退行、テスト失敗、SQLite不整合、通信・通知API、
  公開情報漏洩を検出した場合は工程22で停止します。
- 表示を収めるためにCPU系列を削除、平均化、推測、補間しません。
- v0.3.0の実測履歴と設定は保持し、候補検証前にインストール版を上書きしません。
