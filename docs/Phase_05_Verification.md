# 工程5 SQLite保存 検証記録

## 実装範囲

- 保存先の既定値を
  `~/Library/Application Support/MemoryWatcher/memory-watcher.sqlite3`
  とする
- SQLiteスキーマを版管理し、空のデータベースをversion 1へ取引内で移行する
- 5秒測定値、OS生カウンター、導出値、計算式版、取得品質を列として保存する
- メモリプレッシャー観測を4値の状態と時刻で保存する
- 取得できなかった測定slotを、診断付きの明示的なgapとして保存する
- UTC時刻とシステム稼働時間をマイクロ秒整数、メモリ量をバイト整数で保存する
- バッチ書込みを `BEGIN IMMEDIATE` の単一取引として実行する
- WAL、busy timeout、外部キー検査、整合性検査を有効にする

## スキーマversion 1

| テーブル | 内容 |
|---|---|
| `schema_migrations` | 適用済みスキーマ版と適用UTC時刻 |
| `memory_samples` | 有効な測定値、OS生カウンター、導出値、計算式版、取得品質 |
| `memory_pressure_observations` | `UNKNOWN`・`NORMAL`・`WARNING`・`CRITICAL`の状態観測 |
| `memory_sampling_gaps` | 値を補わなかった測定gapと最後の不整合診断 |

測定値とgapはUTC時刻と稼働時間、プレッシャー観測はそれらに状態を加えた
組が完全に同じ場合に重複を拒否します。同一マイクロ秒に異なる状態が届いた
場合は、別の状態変化として保持します。
保存前検証に合格しない値やSQLiteの64-bit整数で表現できない値は保存せず、
バッチ全体をrollbackします。

## 完了条件と結果

| 完了条件 | 検証結果 |
|---|---|
| スキーマ移行を実行できる | 新規DBをversion 1へ移行し、再オープン後もversion 1を確認 |
| 10万件以上を保存・読出しできる | 10万件を1取引で保存し、件数・先頭・末尾・全行を完全照合。欠損0 |
| 重複を保存しない | 測定値、プレッシャー観測、gapの各重複で制約エラーとなり、バッチ全体のrollbackを確認 |
| 不正値を途中まで保存しない | 2件目に表現不能値を置き、1件目を含むバッチ全体のrollbackを確認 |
| 全記録種別を読戻せる | 測定値、4種類のプレッシャー、診断付きgapの完全一致を確認 |
| 異常終了後に再度開ける | commit直後の別プロセスを`SIGKILL`し、残存WALから別プロセスで1件を読戻し |
| 再オープン後も履歴が残る | 接続解放後と同時接続中の両方でcommit済み履歴を読戻し |
| 並行書込みを安全に直列化する | 100並行書込みでエラー0、保存・読戻し100件、欠損0。Thread Sanitizerにも合格 |
| SQLite整合性検査が通る | 通常、rollback後、10万件後、強制終了後のすべてで`integrity_check = ok` |
| 全ビルド・全単体テストが成功する | `swift build`と全26テストに合格 |

## 異常終了試験

公開成果物に含めない一時検証バイナリを使用し、実装済みストアで有効な
測定値1件をcommitした後、待機中プロセスを `SIGKILL` しました。終了直後は
DB本体に加えてWALと共有メモリファイルが残る状態でした。別プロセスで同じ
DBを開いた結果、保存件数は1、`integrity_check` は `ok` でした。一時ソース、
バイナリ、DBは検証後に削除しました。

## 判定

工程5の保存・移行・取引・再オープン・整合性条件を満たしました。履歴の
保存期限と集約は工程7で実装し、5秒監視との結合は工程6で実装します。
