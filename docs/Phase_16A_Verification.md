# 工程16A 単一ウインドウ統合・描画分離 検証記録

## 工程の範囲

工程16Aは、既存のメモリ、スワップ、メモリプレッシャー、Mac全体CPU、
論理CPU別の現在値と履歴を1つのウインドウへ統合し、現在値更新と履歴Chartsの
描画を分離する工程です。GPU、プロセス別・アプリ別解析、AI、通知、外向き通信、
クラウド保存は含みません。

## 実装結果

- [x] 現在値と履歴を同一ウインドウ内の独立した描画ルートへ分離
- [x] ウインドウ、監視エンジン、現在値host、履歴hostを各1個に固定
- [x] メモリ、CPU全体、論理CPU別、スワップ、Pressureを共通期間で表示
- [x] 表示期間を12時間・24時間・3日に統一
- [x] 12時間・24時間は5秒生データ、3日は1分集約を使用
- [x] 現在値更新だけでは履歴root、履歴世代、履歴読込みを更新しない
- [x] 非表示中も5秒記録を継続し、自動履歴読込みを開始しない
- [x] 選択UTC以前の5秒以内にある実測値だけを照合し、gapを補間しない
- [x] 論理CPU照合を選択UTC近傍の時刻窓へ限定し、保存値の意味を変えず高速化
- [x] 3回の再取得後もOSカウンタが不整合な場合は、値を捏造せず診断付きgapを保持
- [x] 診断付きgapと説明不能な監視失敗を監査上で区別

## 描画分離の決定的観測

現在値を120回公開した試験では、現在値rootは更新されましたが、履歴rootの更新、
履歴読込み、履歴世代の変更はすべて0でした。履歴入力fingerprintと2つのhost identityも
不変で、ウインドウ数と監視エンジン数は各1のままでした。

1・8・16・32論理CPUのUI行列では、CPU indexの欠落・重複、別ウインドウ、
選択値の不一致はありませんでした。最終候補の初期表示9回はすべて2秒未満で、
最速値だけを採用していません。

## 実運転と保存値読戻し

最終Release候補を表示15分、続いて非表示15分で実運転しました。表示区間と
非表示区間で各180件のメモリ記録が増え、非表示中の自動履歴読込みは0回でした。
再表示後、24時間と12時間は各3時点でメモリ、Mac全体CPU、全論理CPUを照合し、
3日は未蓄積の空データとして一致しました。SQLite整合性は`ok`でした。

## incident読戻し

実SQLite読戻しの初回実装はCPU区間終了時刻を選択UTCに使っていました。メモリ値が
同じslot内でわずかに後に取得された場合、正しい値を未測定と判定するため、実際の
メモリ実測時刻を代表時刻にする限定修正を行いました。さらに論理CPU履歴の照合を
全件走査から選択UTC近傍の5秒または1分の時刻窓へ変更し、5秒許容条件を変えずに
初期表示を2秒未満へ戻しました。

30分監査の初回は、製品仕様どおり保存された診断付きメモリgapも説明不能な欠落と
同じFAILにしていました。監査を、3回再取得済みで完全な不整合診断を持つ明示gapと、
監視失敗・診断不完全を区別するよう修正しました。監視失敗や診断不完全は引き続き
FAILです。修正後の全113テストと30分再監査はPASSし、最終再監査ではgap 0、
監視失敗0でした。
