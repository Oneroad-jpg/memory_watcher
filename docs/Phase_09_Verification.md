# 工程9 メニューバー統合 検証記録

## 実装範囲

- メニューバーへmemory chipアイコンと現在の使用量（推定）を表示する
- ステータス項目の左クリックで履歴ウインドウを開閉する
- 右クリックメニューへ現在値、プレッシャー、履歴開閉、ログイン時起動、終了を置く
- 通常起動では履歴ウインドウを自動表示しない
- activation policyを `accessory` とし、Dockへ常時表示しない
- 履歴ウインドウを閉じても監視エンジンとステータス項目を維持する

ステータス項目は `NSStatusBar` の可変幅itemです。測定イベントを受けるたびに
GB表示とプレッシャーをMainActor上で更新します。ウインドウの表示状態は監視の
開始・停止条件に使用しません。

## 操作

| 操作 | 結果 |
|---|---|
| ステータス項目を左クリック | 履歴が非表示なら前面表示、表示中なら非表示 |
| ステータス項目を右クリック | 現在値、Pressure、履歴開閉、ログイン時起動、終了のメニューを表示 |
| 履歴ウインドウのclose | ウインドウだけを閉じ、監視は継続 |
| ログイン時に起動 | `SMAppService.mainApp` の登録状態を切り替え |
| Memory Watcherを終了 | アプリを明示的に終了 |

## 完了条件と結果

| 完了条件 | 検証結果 |
|---|---|
| メニューバーに現在値を表示する | 署名済みアプリでitemの存在と `13.59 GB` の実測表示を読戻し |
| メニューバーから履歴を開閉できる | 実 `NSStatusBarButton` のtarget/actionを2回dispatchし、非表示から表示、再び非表示を確認 |
| 履歴を閉じても監視が止まらない | close後6.5秒でウインドウ非表示、監視 `running`、測定2件を確認 |
| Dockへ常時表示しない | runtime activation policyが `accessory` であることを署名済みアプリから読戻し |
| 通常起動時は画面を強制表示しない | menu bar smoke開始時の履歴ウインドウが非表示であることを確認 |
| ログイン時起動を切り替えられる | `notRegistered` から `enabled`、その後 `notRegistered` へ復元してPASS |
| 終了と設定のmenu commandがある | 履歴、ログイン時起動、終了の全itemにAppKit target/actionがあることを確認 |
| 工程8までの機能が退行しない | 通常画面、close後監視、30日履歴、ログイン項目の全署名アプリ試験がPASS |
| 全ビルド・全単体テストが成功する | debug/release build、Swift format lint、全52テストに合格 |
| 署名済みアプリで動作する | code signature、designated requirement、Info.plist lintに合格 |

## 署名済みアプリの読戻し

メニューバー専用スモーク試験から次を読み戻しました。

- activation policy `accessory`
- 起動時の履歴ウインドウ非表示 `true`
- status item設置 `true`
- status button action dispatch `true`
- buttonから履歴を開いた結果 `true`
- buttonから履歴を閉じた結果 `true`
- menu command設置 `true`
- 現在値 `13.59 GB`
- 監視状態 `running`
- 判定 `PASS`

回帰試験ではタイトル付き履歴ウインドウが1つ表示されました。AppKitが
ステータス項目用に保持する内部ウインドウとは分けて数えています。

30日履歴も8615点を5分集約から読み、履歴読込0.003476秒、画面準備
0.342180秒でPASSしました。menu bar統合によって履歴表示速度は退行していません。

## 検証境界

メニューバーの実測表示値は検証時点のMacの値であり、固定値ではありません。
通常動作では5秒測定ごとに更新されます。24時間実運転と長時間の軽量性は
工程10・11で別に検証し、ここでは完了済みと扱いません。

## 判定

工程9のメニューバー現在値、履歴開閉、Dock非常駐、close後監視、ログイン時
起動設定、明示的終了を満たしました。次は工程10の24時間実運転です。
