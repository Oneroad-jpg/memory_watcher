# 工程7 履歴集約と保存期限 検証記録

## 実装範囲

- 生の5秒測定値を24時間保持する
- 完了した1分bucketごとの平均と実測件数を7日間保持する
- 完了した5分bucketごとの重み付き平均と実測件数を30日間保持する
- プレッシャー、測定gap、ライフサイクル事象を30日間保持する
- 起動直後と1時間ごと、wake後、時計変更後に自動保守する
- 集約作成と期限切れ削除を単一の `BEGIN IMMEDIATE` 取引で実行する

空のbucketには行を作らず、測定されていない値を推測で補いません。

## スキーマversion 3

工程6のversion 2を保持したまま、次のテーブルを取引内の移行で追加しました。

| テーブル | 内容 |
|---|---|
| `memory_aggregates_1m` | 1分開始UTC、実測件数、6項目の平均値 |
| `memory_aggregates_5m` | 5分開始UTC、実測件数、6項目の重み付き平均値 |

平均対象は、物理メモリ、使用量（推定）、有線、圧縮、
キャッシュファイル（推定）、スワップです。1分値から5分値を作るときは、
各1分値をその実測件数で重み付けします。このため、測定件数が異なる1分値を
単純に平均したときの偏りを生みません。

## 取引順序

1. 完了済みの生データから1分値をupsertする
2. 完了済みの1分値から5分値をupsertする
3. 集約済み1分値が存在する24時間超の生データだけを削除する
4. 集約済み5分値が存在する7日超の1分値だけを削除する
5. 30日超の5分値と低頻度事象を削除する
6. 全処理をcommitする

途中で1つでも失敗した場合は集約作成を含めて全処理をrollbackします。
集約前、または対応する次段集約が存在しない元データは削除しません。

## 検証境界

31日試験は保持期限の境界を明確にするため、0日から31日前まで各UTC日に
測定値を置くfixtureです。実際の5秒間隔31日相当DBの容量は工程11、
30日履歴の読出しと表示速度は工程8で別に検証します。ここでは完了済みだと
扱いません。

## 判定

工程7の段階集約、重み付き平均、保存期限、集約成功後だけの整理、自動実行、
移行、rollback条件を満たしました。履歴期間の選択とグラフ表示は工程8で
実装します。
