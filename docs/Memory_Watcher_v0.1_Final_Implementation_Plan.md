以下を「v0.1確定工程表」とすれば、必要要件と各工程の完了判定を一貫して管理できます。

進行順は固定します。

`要件固定 → 計測検証 → SQLite → 常時監視 → 集約処理 → グラフ → メニューバー → 24時間検証 → アプリ化`

## v0.1確定工程表

| 工程 | 実装内容・成果物 | 工程の完了条件 |
|---|---|---|
| 0. 要件固定 | 通知なし、外部通信なし、プロセス別解析なし。5秒測定、12時間・24時間・3日表示。スリープ中は空白。データはローカルSQLiteのみ。公開リポジトリには製品成果物だけを保存する。 | 対象機能と対象外機能が文書化されている。「Activity Monitorと同傾向」であり、数値・圧力曲線の完全一致は保証対象外と明記されている。公開境界が文書化され、未決定項目がない。 |
| 1. プロジェクト基盤 | 独立したmacOSアプリを作成。Swift、SwiftUI、Swift Charts、SQLiteを使用。VS Codeで編集し、AppleのSDKでビルドする。 | クリーンな状態からビルドできる。単体テストを実行できる。空のアプリが起動する。現在の作業用リポジトリとは分離されている。 |
| 2. メモリ計測プロトタイプ | UIを作る前に、5秒ごとにメモリ統計を取得する。UTC時刻とシステム稼働時間も記録する。 | 10分以上連続測定できる。物理メモリ、使用量、有線、圧縮、キャッシュ、スワップが負数や異常値にならない。想定された回数の測定値が得られる。 |
| 3. Activity Monitorとの照合 | アイドル時、通常使用時、高負荷時の3条件で同時測定する。各表示項目の取得元と計算式を固定する。 | 各数値の差を説明できる。完全一致しない項目は「推定」または独自名称にする。説明不能な差が残る場合はHOLDとし、次工程へ進まない。 |
| 4. メモリプレッシャー取得 | OSが返すnormal・warning・criticalの変化を監視する。連続的な独自スコアは作らない。 | 状態変化が時刻付きで保存できる。起動直後の状態を取得できない場合は、推測せず`UNKNOWN`として保存する。Activity Monitorと同じ連続曲線だと偽って表示しない。 |
| 5. SQLite保存 | 生の測定値、導出値、計算式バージョン、UTC時刻、稼働時間をSQLiteへ保存する。トランザクションとスキーマ移行を実装する。 | 10万件以上の試験データを保存・読出しできる。重複や欠損がない。異常終了後も再度開ける。`PRAGMA integrity_check`が`ok`になる。 |
| 6. 常時監視とライフサイクル | アプリ起動中はバックグラウンドで5秒測定する。ログイン時起動を設定可能にする。スリープ・復帰・時計変更・再起動を識別する。 | ウインドウを閉じても測定が続く。ログイン時起動の有効・無効が機能する。スリープ中に偽の測定値を生成しない。復帰後に測定を再開し、空白期間を保持する。 |
| 7. 履歴集約と保存期限 | 生データは24時間、1分平均と互換用5分平均は3日保持する。集約成功後にだけ元データを整理する。 | 4日分の模擬データで境界が正しい。平均値の計算が単体テストを通る。集約前のデータを削除しない。3日を超えたデータだけが整理される。 |
| 8. 履歴グラフ | 12時間・24時間・3日を切り替える。使用量の構成、圧縮、スワップ、プレッシャー状態を表示する。時刻とGB値をポイント表示する。 | 各期間で正しいデータが選ばれる。スリープ区間を線で補間せず空白表示する。単位、軸、凡例が読める。3日画面が対象Macで2秒以内に表示される。 |
| 9. メニューバー統合 | メニューバーに現在値を簡潔に表示し、クリックすると履歴ウインドウを開く。終了とログイン時起動の設定を置く。 | メニューバーから履歴を開閉できる。履歴ウインドウを閉じても監視が止まらない。Dockへ常時表示しない。通知機能を持たない。 |
| 10. 24時間実運転 | 通常利用状態で24時間連続運転し、Activity Monitorと定期的に照合する。途中でスリープと復帰も実施する。 | 起動中の説明不能な測定欠落がゼロ。再起動後も履歴が残る。スリープ中の偽データがない。Activity Monitorとの差異表を作成し、すべて説明可能になっている。 |
| 11. 軽量性・非通信検証 | CPU、アプリ自身のメモリ、SQLite容量、外部接続を確認する。 | アイドル時平均CPU使用率1%未満を目標とする。24時間でメモリが単調増加しない。3日保持上限のDBが設定上限内に収まる。外向き通信と通知が発生しない。SQLite整合性検査が通る。 |
| 12. アプリ化・最終読戻し | バージョン付きの`.app`を生成して実際にインストールする。署名、起動、ログイン時起動、保存先を確認する。 | 生成物のバージョンとSHAを記録する。インストール済みアプリを起動して新しい測定値がSQLiteへ書かれる。履歴画面でその値を読める。ビルド成功だけで完了扱いにしない。 |

## 最終完成ゲート

次の全項目を満たした場合にのみ、v0.1完成とします。

- 24時間連続動作し、起動中の説明不能な欠落がない
- 再起動後も履歴が残る
- スリープ区間が空白として正しく表示される
- 12時間・24時間・3日を切り替えられる
- 3日表示が実用的な速度で開く
- 監視アプリ自身のメモリが増え続けない
- Activity Monitorとの差を項目ごとに説明できる
- メモリプレッシャーの不明状態を推測で埋めない
- 通知、外部通信、クラウド保存を行わない
- プロセス別解析を行わない
- 公開成果物に端末固有情報、認可情報、受領記録、非公開ログを含めない
- SQLiteの整合性検査が`ok`
- インストール済みアプリで実際の記録と読戻しを確認済み

この工程表なら、「アクティビティモニタのメモリ状態を常時記録し、後から見やすいグラフで確認する」という目的に対して必要十分です。完全なActivity Monitor複製ではなく、履歴監視アプリとして完成を判定できます。
