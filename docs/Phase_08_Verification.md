# 工程8 履歴グラフ 検証記録

## 実装範囲

- 24時間・7日・30日の表示期間をsegmented controlで切り替える
- 24時間は生データ、7日は1分集約、30日は5分集約を読み出す
- 使用量（推定）を、その他使用量（推定）・有線・圧縮の積層で表示する
- 物理メモリ、スワップ、メモリプレッシャーを同一時刻軸で表示する
- 選択時刻と使用量6項目をGB単位で表示する
- sleep、測定gap、再起動、長い測定間隔を線で補間しない
- 30日相当の表示点を描画用に最大1200点へ間引く

描画用の間引きは表示だけに適用します。SQLiteの履歴と選択点の検索には
全測定点を保持し、連続区間の両端も必ず描画対象へ残します。

## 期間と保存層

| 表示期間 | 読出し元 | 想定間隔 |
|---|---|---:|
| 24時間 | 生の測定値 | 5秒 |
| 7日 | 1分集約 | 60秒 |
| 30日 | 5分集約 | 300秒 |

期間外の値は読出し後に除外し、UTC時刻順に並べます。集約値の
その他使用量（推定）は、使用量（推定）から有線と圧縮を引いて算出します。

## 空白とプレッシャー

次のいずれかが隣接点の間に存在する場合、新しい連続区間を開始します。

- sleepからwakeまでの区間
- 明示的な測定gap
- rebootまたは時計変更
- 期待間隔の2.5倍を超える時刻差

Swift Chartsの系列識別子へ連続区間番号を含めるため、異なる区間を線や面で
接続しません。sleep区間は薄い帯でも示します。

プレッシャーは `UNKNOWN`・`NORMAL`・`WARNING`・`CRITICAL` の状態区間として
表示します。期間開始時点より前の既知状態がなければ `UNKNOWN` を保持し、
推測で正常状態に置き換えません。

## 署名済みアプリの読戻し

隔離した一時SQLiteへ30日分の5分測定fixtureを配置し、2時間のsleep区間だけを
欠測にしました。署名済みReleaseアプリの30日画面から次を読み戻しました。

- 履歴点8615件
- 読出し元 `fiveMinutes`
- sleep区間1件
- 履歴読込0.004174秒
- 画面準備0.772877秒
- ウインドウ表示あり
- 判定 `PASS`

画面上では使用量の積層、物理メモリの破線、スワップ、プレッシャー状態、
選択点の詳細を確認しました。sleep位置では使用量とスワップのどちらも
前後の点を線で接続していません。

既存機能の回帰確認として、通常の起動スモーク試験は監視状態 `running`、
初回測定1件、表示ウインドウ1でPASSしました。ウインドウを閉じる試験も、
6.5秒後に画面非表示、監視状態 `running`、測定2件でPASSしました。

## 検証境界

30日fixtureは履歴選択、描画速度、欠測表示を再現可能にする検証専用データで、
通常の保存先には書き込みません。実際の30日連続運転は工程10、アプリ自身の
CPU・メモリとDB容量は工程11で別に検証します。ここでは完了済みだと扱いません。
