# 工程10 24時間実運転 検証記録

## 実装範囲

- 実運転の開始時刻、終了条件、履歴マーカー、初期整合性を固定する
- 24時間の有効サンプル、明示的な測定gap、sleep・wakeを監査する
- Activity Monitorの実表示とMemory Watcherの同時刻付近の値を照合する
- 説明不能な欠落、sleep中の偽サンプル、予期しない再起動をHOLDにする
- 監査結果を `PENDING`・`PASS`・`HOLD`で機械判定する

工程10では、実運転用の監査ロジックとコマンドラインツールを追加しました。
監査の入力は製品DBと分離し、公開リポジトリには実機固有の生ログや一時記録を
保存しません。

## 24時間監査結果

固定した24時間の終了条件を過ぎた後、次の結果を読み戻しました。

| 確認項目 | 実測結果 |
|---|---:|
| 判定 | `PASS` |
| 実運転時間 | 87,321.128秒 |
| 期待測定slot | 17,089件 |
| 記録済み有効sample | 17,072件 |
| 明示的な測定gap | 19件 |
| 区間境界の許容slot | 3件 |
| 説明不能な欠落 | 0件 |
| 完了したsleep・wake区間 | 2件 |
| sleep区間内のsample | 0件 |
| 有効なActivity Monitor照合 | 3件 |
| 監査区間外として除外した照合 | 1件 |
| 予期しないアプリ再起動 | 0件 |
| 監査中のシステム再起動 | 0件 |
| SQLite整合性 | `ok` |
| 未達条件 | なし |
| HOLD理由 | なし |

Activity Monitorは丸められた非同期の表示値、Memory Watcherは公開VM
カウンターから算出する時刻付き推定値です。3件の有効な照合について、物理
メモリ、使用量、確保されているメモリ、圧縮、キャッシュ、スワップの差を
この取得時刻と計算方法の違いで説明できることを確認しました。監査区間終了後の
追加照合は判定へ混ぜず、区間外として除外されています。

## 再起動後の履歴読戻し

24時間監査がPASSした後にMacを再起動し、同じSQLiteから次を読み戻しました。

- 再起動前の有効sample 13,282件
- 再起動後の有効sample 4,044件
- 再起動直前と再起動後の両側に時刻付きsampleが存在
- `LAUNCH`と`REBOOT_DETECTED`が同じ再起動として記録済み
- 監査開始前の履歴マーカーを1分集約から読戻し可能
- 再起動後も新しい5秒測定が継続
- SQLite `integrity_check`は `ok`

これにより、再起動をまたいで既存履歴を失わず、新しい測定を同じDBへ追記し、
履歴画面が利用する集約値も保持できることを確認しました。

## 検証境界

- Activity Monitorとの数値および連続的なメモリプレッシャー曲線の完全一致は
  保証しません。
- 24時間監査は通常利用中の1台のApple Silicon Macで実施しました。
- CPU、GPU、プロセス別・アプリ別解析は工程10の対象外です。
- 長期のCPU使用率、アプリ自身のメモリ増加、DB容量、外向き通信は工程11で
  別に検証します。
- 署名済み配布アプリの生成とインストール済み実体の読戻しは工程12で検証します。

## 判定

24時間連続運転、sleep区間の空白、説明不能な測定欠落ゼロ、Activity Monitor
との差異説明、SQLite整合性、再起動後の履歴保持を確認しました。工程10は
`PASS`です。次は工程11の軽量性・非通信検証です。
